MAGICXBF APPLICATION ARCHITECTURE

This document describes the runtime architecture of the generated MagicXBF application.

============================================================
1. OVERVIEW
============================================================

The application is a client-server web application designed for 3D CAD interaction. It consists of a Python/Quart backend providing a JSON API and a JavaScript/Three.js frontend for rendering and user interaction.

The architecture strictly follows the specified pipeline:
UI → Frontend State → API → Backend Engine → Geometry Kernel → Tessellation → Viewport

============================================================
2. BACKEND ARCHITECTURE
============================================================

The backend is built using the Quart async web framework, allowing it to handle long-running CAD operations without blocking.

- **Web Server (`app.py`):**
  - The main entry point for the application.
  - Defines all API endpoints (e.g., `/api/command`, `/api/tessellate`).
  - Manages HTTP requests and responses.
  - Instantiates a single, stateful `Engine` object on startup.
  - Uses `asyncio.to_thread` to delegate synchronous, CPU-bound CAD tasks to a thread pool, keeping the server responsive.

- **Engine Facade (`engine/main.py`):**
  - The `Engine` class is the primary interface to all backend CAD functionality.
  - It holds the current `Document` state.
  - It dispatches requests to specialized subsystems (Operations, IO, Tessellator).
  - It contains the logic for the Engineering Assistant, parsing natural language and converting it into internal commands.

- **Document Model (`engine/document.py`):**
  - The `Document` class represents the entire scene, containing a dictionary of `Part` objects.
  - The `Part` class represents a single solid body, holding its name, ID, display properties, and a reference to its underlying geometry object from the CAD kernel. It also caches its tessellation data.

- **CAD Kernel Abstraction (`engine/adapter.py`):**
  - An abstract base class `CadKernelAdapter` defines the contract for all geometry operations (primitives, booleans, tessellation, etc.).
  - `CadQueryAdapter` is the concrete implementation that wraps the `cadquery` library. All real geometry creation and modification happens here.
  - `NoCadAdapter` is a fallback that raises `NotImplementedError` if `cadquery` is not installed, enabling graceful degradation.

- **Subsystems:**
  - **`engine/operations.py`:** Contains the logic for modifying geometry (e.g., `create_primitive`, `boolean_operation`). It uses the `CadKernelAdapter`.
  - **`engine/io_system.py`:** Manages all file import and export. It uses the adapter for B-Rep formats (STEP, IGES) and includes logic for the native `.xbf` format (JSON with base64-encoded B-Rep strings).
  - **`engine/tessellator.py`:** Responsible for converting B-Rep geometry from the `Part` objects into triangular meshes (vertices, indices, normals) suitable for rendering by the frontend.
  - **`engine/capabilities.py`:** Detects which libraries (`cadquery`) are installed at startup and reports the available features to the frontend.

============================================================
3. FRONTEND ARCHITECTURE
============================================================

The frontend is a modular, single-page application built with modern JavaScript (ESM) and Three.js.

- **Main Application (`main.js`):**
  - The entry point (`MagicXBFApp` class).
  - Instantiates and coordinates all other frontend modules (UI, Viewport, API, State, etc.).
  - Defines the main application loop and handles high-level API responses.

- **UI Controller (`ui.js`):**
  - The `UI` class manages all DOM elements and user interactions outside of the 3D viewport.
  - It handles clicks on toolbar buttons, panel toggles, and tab switching.
  - It dispatches commands to the `API` client.
  - It updates the DOM (Assembly Tree, Properties Panel, Status Bar) in response to state changes.

- **State Manager (`state.js`):**
  - A simple, centralized `State` object that holds the client-side application state, including the current selection (`Set` of part IDs), list of parts, and engine capabilities.
  - When state is changed via `State.set()`, it fires a global `state:change` event that other modules (like `UI` and `Viewport`) listen to.

- **API Client (`api.js`):**
  - The `ApiClient` class provides a clean, promise-based interface for all communication with the backend JSON API.
  - It abstracts away `fetch()` calls and handles request/response logging, error handling, and status updates.

- **3D Viewport (`viewport.js`):**
  - The `Viewport` class encapsulates all Three.js rendering logic.
  - It manages the `THREE.Scene`, `THREE.Camera`, and `THREE.Renderer`.
  - It implements camera controls (`OrbitControls`) and selection via raycasting.
  - The `loadMeshes` method takes tessellation data from the backend and creates/updates `THREE.Mesh` objects.
  - It listens to selection state changes to apply visual highlighting to objects.
  - It implements the interactive 16-sided view cube for camera orientation.

- **Telemetry (`telemetry.js`):**
  - A centralized logging utility. All modules call `Telemetry.log()` to report significant events (UI clicks, API calls, errors).
  - It writes structured logs to the console and to the Telemetry panel in the UI for debugging.

- **Engineering Assistant (`assistant.js`):**
  - Manages the UI for the assistant.
  - Captures user input and sends it to the `/api/assistant` endpoint.
  - Displays responses and errors in the assistant's log panel.

============================================================
4. REQUEST FLOW EXAMPLE: CREATE BOX
============================================================

1.  **User** clicks the "Box" button in the top toolbar.
2.  **`ui.js`** `handleToolbarClick` captures the click. It identifies the action as `data-primitive="box"`.
3.  **`ui.js`** calls `this.app.API.sendCommand('create_box')`.
4.  **`api.js`** sends a POST request to `/api/command` with `{"command": "create_box"}`.
5.  **`app.py`** (Quart) receives the request and calls `CAD_ENGINE.execute_command('create_box', ...)` in a separate thread.
6.  **`engine/main.py`** (`Engine` class) calls `self.ops.create_primitive('box', ...)`.
7.  **`engine/operations.py`** calls `self.adapter.create_box(...)`.
8.  **`engine/adapter.py`** (`CadQueryAdapter`) executes `cadquery.Workplane().box(...)` to create the B-Rep geometry.
9.  A new `Part` object is created and added to the `Engine.document`.
10. **`app.py`** receives a success result from the engine and sends a JSON response to the client.
11. **`main.js`** (`handleApiResponse`) receives the success response. It immediately calls `this.API.tessellate()`.
12. **`api.js`** sends a POST request to `/api/tessellate`.
13. **`app.py`** calls `CAD_ENGINE.get_tessellation()`.
14. **`engine/main.py`** iterates through all parts in the document, calling `self.tessellator.tessellate_part()` for each.
15. **`engine/tessellator.py`** uses the `CadQueryAdapter` to generate a triangular mesh from the B-Rep.
16. The server returns a JSON object containing the mesh data (vertices, indices, normals) for all parts.
17. **`viewport.js`** receives the mesh data via `loadMeshes()`, clears the old scene, and creates new `THREE.Mesh` objects.
18. **`ui.js`**, listening to the state change, updates the Assembly Tree with the new part.
19. The new box appears in the viewport.
